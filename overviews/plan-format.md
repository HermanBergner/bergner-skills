# plan-format

The house format for a phased implementation or design plan — a status-stamped document you write before any code, so the shape of the work and the reasoning behind it are clear up front.

## When to use it

When writing, structuring, or reviewing a plan for a new capability or a multi-step change — before the first line of code.

## What you get

- A TL;DR and recorded decisions that capture *why this shape*
- Security requirements treated as first-class, not an afterthought
- An architecture sketch and tasks scoped one-PR-each, in an explicit order
- Deferred / out-of-scope called out, plus a devil's-advocate pass and a clean handoff
