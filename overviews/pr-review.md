# pr-review

The house discipline for pull requests — the bar a change is held to before it merges, whether you're opening your own PR or reviewing someone else's.

## When to use it

When opening a PR for review, or reviewing one, and you want it checked against the house standard rather than waved through.

## What you get

- One task = one PR, **opened not merged** — the human reviews and squash-merges
- Every changed line traced back to the request; scope creep and stray refactors flagged
- Verification recorded in the PR itself
- Security criteria reviewed first-class, not bolted on at the end
